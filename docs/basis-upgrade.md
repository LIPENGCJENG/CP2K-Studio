# 基组与赝势模块升级

本次保留原有三栏布局、深色主题和参数模型，不重建应用。程序入口仍为 `python main.py`。

## 修改与新增文件

新增：

- `core/database_format.py`：统一条目、Alias、质量/标签/q/XC 元数据、文件及条目指纹、原生数据行边界。
- `core/basis_database.py`：按 nset、壳层维数、指数行和收缩系数解析，隔离不满足严格检查的条目。
- `core/potential_database.py`：解析 GTH 的电子组态、局域项、非局域三角矩阵、NLCC 和全电子条目；NA 不提供候选。
- `core/database_manager.py`：按优先级扫描真实文件，检查版本/指纹，记录来源/缺失/冲突状态；提供用户主动触发的固定版本下载。
- `core/database_resources.py`：解析实际资源路径；多来源赝势生成单一文件，避免重复不可重复的 CP2K 关键词。
- `core/kind_recommender.py`、`core/kind_validator.py`：来自实际数据的候选推荐，以及逐 KIND 的元素、q、XC、方法、指纹和搜索优先级检查。
- `core/input_import.py`：保守导入已有 INP 中受支持的参数和结构，匹配真实数据库；未支持配置通过提示报告。
- `ui/database_dialog.py`：数据库管理和后台显式下载。
- `data/cp2k-2026.1/`：未经修改的固定版本官方文件和带 commit/URL/SHA-256 的清单。
- `tests/test_databases.py`、`tests/test_kind_workflow.py`：真实数据库解析、版本/冲突、兼容性、GUI、往返、多文件导出及导入测试。

修改：

- `core/models.py`：保留旧格式兼容性，增加 KIND 的 ELEMENT、来源引用/指纹、推荐记录、每原子 KIND 标签、数据库设置、多赝势源字段。
- `ui/kind_panel.py`：每行独立的可搜索下拉控件、过滤器、状态、显式推荐；高级模式保留文件配置。
- `ui/main_window.py`、`ui/structure_panel.py`：即时同步选择、Error/Warning/Info、INP 导入、数据库入口、可编辑原子 KIND。
- `core/generator.py`、`core/validator.py`、`core/structure.py`、`core/project_io.py`：整合真实数据校验、KIND/ELEMENT、多个文件、赝势合并、相对路径打包和新元数据持久化。
- 相关原有测试：将旧的“只要文件名即可”的断言升级为真实数据检查；仍保留原有 GLOBAL、SCF、MOTION 和官方 ENERGY/GEO_OPT 回归基准。
- `README.md`：新增操作、来源、校验和限制说明；依赖未新增。

## 数据如何定位

1. 项目数据库设置中指定的 CP2K data 目录。
2. `CP2K_DATA_DIR`、可执行文件相邻的 share 路径，以及常见 macOS/Linux 路径。
3. 用户缓存（macOS：`~/Library/Caches/CP2K-Studio/2026.1`；Linux：`$XDG_CACHE_HOME/CP2K-Studio/2026.1` 或 `~/.cache/CP2K-Studio/2026.1`）。
4. 应用随附的、固定到官方 v2026.1 release commit 的缓存。

用户主动添加的库和项目记录引用也会扫描。所有文件先检查存在性。与固定官方清单指纹一致的数据可确认版本；没有可确认版本的数据默认排除。用户可主动添加自定义文件并声明 2026.1，界面保留“用户声明，非官方认证”状态。不从第三方库补齐数据，不在启动时联网。

点击数据库管理中的官方下载按钮才会访问 [CP2K 官方仓库](https://github.com/cp2k/cp2k)。固定 commit 的所有文件下载到暂存目录，验证清单指纹及可解析内容后再替换缓存；下载失败保留原缓存。并非追踪移动分支或自动升级到其他 CP2K 版本。

官方库文件中存在 NA 和个别不完整记录。程序保留原始库文件，不猜测修正。数据库管理中的状态/说明和选中行详情会报告被排除的具体名称、原因、文件指纹；其他经过解析的条目可以继续使用。

## 在 GUI 中选择

1. 导入结构，明确电荷、多重度、XC 等必要信息。
2. 打开第 05 页。每行的基组和赝势下拉框只针对该行真实 ELEMENT 提供候选。
3. 输入名称或 Alias 关键字搜索；也可用上方的质量、来源、XC、q 过滤器。Alias 与主名称是同一条记录。
4. 在候选中实际选中一项，模型与 INP 立即更新。单纯输入搜索文本不会把任意字符串作为参数。
5. 当前选择在重筛、结构同步和项目重开时保留；筛选外的当前选项会保留展示。缺失/改变的数据不会静默换成同名条目。
6. 需要推荐时，点击推荐按钮，查看实际存在的候选，明确选中一行并应用。没有候选时不修改配置。
7. 自定义库和文件配置在高级模式中操作。需要区分同种元素时，可在结构页 KIND 列设置 O1/O2 等标签，各自选择。

## 兼容性判断

- 基组 q 从真实主名称或 Alias 中明确的 `-qN` 提取；赝势也核对电子组态总和。两者可确认且不同是 Error。缺少 q 是 Warning“无法自动确认”，不视为已兼容。
- XC 从实际名称的明确标签解析，与 DFT 页面当前 XC 比较。不同或不明确给出 Warning，不把名称相符描述成物理兼容性证明。
- 当前计算方法固定为 GPW/GTH。全电子势和明确的全电子基组在此流程中是 Error。
- 所有需要的原子 KIND 都必须有真实存在、对应正确元素且来源文件可用的条目。数据库版本/指纹变化、基组被高优先级同名不同内容遮蔽等会阻止导出。
- 普通基组质量差异只作 Info，不阻止导出。UZH 尚无独立验证的对应协议表，不自动推荐；手动选择时提示协议未验证，并阻止跨 UZH/常规库混作同一协议。

## 文件生成与持久化

基组文件去重并保持有意义的查询顺序。CP2K 2026.1 XML 标记 `BASIS_SET_FILE_NAME` 可重复，而 `POTENTIAL_FILE_NAME` 不可重复。因此多来源赝势会合并**实际选中的**原始数据块到 `studio_potentials.dat`，只保留所选名称，排除通用 Alias 冲突。相同元素/名称选择不同内容会报错，不通过重排掩盖冲突。

导出计算包复制真实源文件、生成相对路径 INP，并保存来源/版本/指纹和推荐记录。合并文件的注释记录源路径及指纹；项目 JSON 保留未合并的原始选择。包内项目重开后可再次导出。其他 DFT、SCF、MOTION 参数使用原模型和生成流程。

## 测试与限制

测试命令：`python -m pytest -q`。覆盖原有测试及新增真实文件解析、主名/Alias、Ba/Ti/O 过滤、q/XC、缺失数据、未知版本、修改指纹、重复名称、文件优先级、下载指纹/失败保留、无网络启动、GUI 选择即时同步、筛选保留、推荐记录、旧项目/INP、两个 KIND 指向同元素、多基组/多赝势导出和二次导出。

实际开发环境为 macOS / Python 3.12，GUI 使用 Qt offscreen 自动测试并检查窗口截图。Windows/Linux 未做实机测试；本环境未安装 CP2K，因此没有调用 CP2K 本体做运行验证或数值能量对比。XML 语法校验使用随附的 2026.1 规范。第三方 cp2k-input-tools 的 ElementTree 弃用警告保留可见。

INP 导入仅恢复当前模型支持的范围，不承诺任意 INP 完整无损往返。UZH 协议的科学适用性、不同泛函的物理迁移性及最终数值收敛性仍需用户依据原始方法资料和实际计算验证。
